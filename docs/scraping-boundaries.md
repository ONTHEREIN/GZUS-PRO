# 学校系统数据访问边界

本文档约束软帮手对广州软件学院相关系统的访问。目标是只完成用户主动请求或已明确授权的校园服务，降低对上游系统的压力并避免越权读取。

## 当前范围

### 教务系统

允许读取当前登录学生自己的：

- 学生基本信息和头像；
- 课表、考试安排、成绩、学分和考勤；
- 教务通知及其详情。

优先复用 `services/api/app/vendor/school_sdk` 已有能力。缺失能力只能通过当前已登录会话的 `proxy_request` 补齐，并必须在对应路由中做账号范围和响应格式校验。

### 办事大厅

允许在用户主动进入或提交相关功能时访问：

- 校园通知、办事事项、应用和进度；
- 教师查找；
- 请假预览、表单填写和附件上传。

不得在后台替用户发起未授权的申请、审批或其他业务操作。用户提交的请假内容和附件只能用于当前业务流程。

### 一卡通与生活缴费

- 只使用后端受保护的服务凭据访问一卡通/融校云接口；
- 只返回当前登录学生主动绑定宿舍的余额和消费数据；
- 不读取、不缓存、不展示其他宿舍或其他学生的数据；
- 余额提醒必须绑定当前账号和当前宿舍。

### 后台提醒

只有用户明确开启“后台持续通知”后，才允许使用加密的自动登录凭据按计划访问学校系统，检查课程、考试、成绩、考勤和通知变化。关闭授权、凭据撤销或会话失效后必须停止该访问。

## 明确禁止

- 未登录或跨账号读取个人教务数据；
- 批量枚举学号、宿舍、教师或其他业务对象；
- 抓取与当前功能无关的页面、附件或个人信息；
- 绕过学校系统的验证码、限流、权限或会话约束；
- 将学校系统数据用于广告、画像、商业销售或向其他用户披露；
- 在没有用户明确操作的情况下代填、提交或修改办事大厅业务；
- 把密码、Cookie、CAS ticket、ProxyTicket、推送令牌或私有配置写入日志、测试数据或仓库。

## 缓存与请求控制

- 缓存键必须包含账号和资源参数，不能跨账号复用；
- 失败兜底缓存必须带时间并遵守资源最大存活期，不能把过期数据伪装成实时结果；
- 后台轮询使用账号级共享学校会话，避免同一账号被多个设备重复登录；
- 新增轮询任务前先评估频率、失败重试和上游限额，并提供明确的停止条件；
- 上游返回异常、登录失效或数据结构变化时，记录脱敏后的错误并停止无意义重试。

## 变更检查

新增学校系统字段、路由、轮询任务或第三方接口时，至少检查：

1. 是否只处理当前账号和当前功能所需数据；
2. 是否需要更新[隐私政策](./privacy-policy.md)、[服务协议](./terms-of-service.md)和 API 文档；
3. 是否存在新的凭据、权限、缓存或删除路径；
4. 是否有真实账号、Cookie 或个人数据进入测试、日志和发布产物；
5. 是否覆盖了上游失败、限流、会话过期和重复请求场景。
