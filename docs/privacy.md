# 内部隐私规范

> 本文件是开发团队的技术检查清单，不替代面向用户的[完整隐私政策](./privacy-policy.md)。任何实现与本文不一致时，应先修正实现或同步更新隐私政策，不能用文档掩盖实际行为。

## 凭据与认证

- 账号密码只用于学校统一身份认证；请求和日志不得泄露密码。
- 用户勾选“记住密码并自动登录”后，密码和自动登录凭据只能通过 `flutter_secure_storage` 管理；普通 `SharedPreferences` 不得保存密码。
- 后端不得保存明文密码。为支持会话恢复或用户主动开启后台持续通知，可以保存经 Fernet 加密的学校会话 Cookie、认证令牌和自动登录凭据。
- CAS ticket、ProxyTicket、一次性 `ssoCode` 和移动端 WebView 临时 Cookie 只用于完成登录，完成后应清理或使其失效。
- 前端只在普通偏好存储中保存 sessionId、学生姓名/学号、开关设置和非敏感缓存；服务端会话和学校会话必须按账号隔离。
- `openid`、`unionid`、VAPID 私钥、APNs 私钥、Shiply 私钥和内部 API 密钥只能存在于后端或受保护的构建环境，不能出现在接口响应、前端状态、日志或文档中。

## 数据最小化

- 学校系统只读取当前功能所需的个人教务数据；不得为了调试或展示读取其他账号、其他宿舍或无关页面。
- 生活缴费只处理当前用户主动绑定的宿舍；接口和日志不得暴露其他宿舍余额。
- 天气功能仅在用户授权后使用近似位置；位置只用于天气查询，不用于身份画像或持续跟踪。
- 推送只保存投递所需的 Web Push 订阅、iOS APNs/ActivityKit 令牌和安装实例标识；登出或撤销授权时应注销对应注册信息。
- 用户反馈中的联系方式、诊断日志和附件属于用户主动提交的数据，应限制管理员访问并避免写入不必要的敏感信息。

## 存储与清理

- 生产数据库使用 PostgreSQL。账号级学校会话 Cookie/认证令牌和后台通知凭据必须加密后存储。
- 教务、通知、天气和缴费缓存必须带账号或明确的资源范围，不能跨账号复用。
- 登出时清除本地认证材料、学校 Cookie、推送注册和账号缓存，并撤销服务端应用会话；后台持续通知和课程提醒也要停止。
- 后台通知授权关闭或长期凭据撤销后，删除对应的加密凭据和配置；过期的通知、令牌和临时票据按清理任务处理。
- 测试和演示只能使用假账号。真实账号、密码、Cookie、验证码 token、推送令牌和生产数据库内容不得进入仓库、快照、日志或测试报告。

## 日志与错误处理

- 日志使用结构化字段；禁止输出密码、Cookie、授权头、完整 token、个人附件内容或包含私密 token 的 URL。
- 记录异常时保留类型和可行动的上下文，但先确认错误文本不会回显敏感请求参数或上游响应。
- 上游服务错误要明确区分认证失败、网络失败、数据解析失败和配置错误，不得通过静默降级掩盖隐私或权限问题。
- 公众号 RSS 地址包含私有 token 时，所有日志、管理后台响应和错误消息必须经过脱敏。

## 发布前检查

- 检查[隐私政策](./privacy-policy.md)、[用户服务协议](./terms-of-service.md)、README、登录页摘要和“关于”页是否与本次功能一致。
- 检查生产 API 是否只通过 HTTPS 暴露，测试地址、密钥和本地账号是否未被打包进发布产物。
- 检查退出登录、撤销后台通知、删除推送令牌和管理员审计日志相关路径。
- 新增权限、第三方 SDK、数据字段或持久化表时，必须同时补充用户告知和保留期限说明。
